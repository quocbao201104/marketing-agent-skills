# Brand identity input sufficiency — targeted regressions

Status: **REGRESSION CONTRACT — NOT A LIVE IMAGE-GENERATION RESULT**

## Failure and correction scope

Contribution risk: **Level 2 — bounded controller behavior**.

```text
Create a logo for a named project whose functions are known
→ treat project understanding as sufficient design input and execute directly
→ choose a metaphor and assume a deployment surface before resolving their basis
→ the asset may solve the wrong identification job or fail in its actual use
→ distinguish project facts from sufficient identity inputs at the controller boundary
```

The triggering evidence is a user-reported episode: the agent selected a
letterform/open-book concept, assumed plugin-icon use, and produced a text-heavy
composition without verifying small-context fitness. Its subsequent self-report
acknowledged those omissions. This is not an independently reproduced full trace.
The existing Chapter 15 already governs strategy consumption, exploration,
deployment evaluation, and preview/master status; retrieval addresses need no change.

## I01 — Project functions known, identity inputs unexamined

**Input:** Use the skill to create a logo for Vietnam Business Law Practitioner.
The retained context describes an AI-agent skill for Vietnamese business/legal
decisions. Audience, intended recognition, and actual use have not been established.
The user wants progress now.

**Expected:** Inspect available context, relevant project documentation and existing
assets for decision-changing inputs. Distinguish supported facts from proposed
choices. Resolve only material gaps through the existing uncertainty policy. Use
the relevant `brand-identity` guidance before choosing an unresolved identifying
cue. If a material input remains unavailable, ask the smallest useful question or
offer clearly provisional exploration that does not silently settle that input.

**Failure:** Infer a final metaphor from the name/function alone; treat assumed
plugin-icon use as established; claim readiness after checking only image defects.

## I02 — Context supplies enough; no repeated intake

**Input:** Create a new logo. The retained project brief establishes the audience,
desired identification, required compact and horizontal uses, and constraints.
The user delegates the visual choice. No existing equity needs preservation.

**Expected:** Consume that state, use identity guidance for the open visual choice,
select within delegated authority, produce, and check the required uses. No repeated
brief questionnaire, extra approval, fixed option count, or mandatory strategy read.

**Failure:** Treat every logo request as an unresolved brief; wait for approval of
an already delegated decision; require all possible brand fields to be filled.

## I03 — Approved master, mechanical production

**Input:** Export this approved logo unchanged to the supplied PNG dimensions.

**Expected:** Execute directly. Preserve the approved identity and supplied sizes.

**Failure:** Reopen positioning or identity exploration; require a brief or deep read.

## I04 — Exploration explicitly requested under uncertainty

**Input:** Audience is still being investigated. Make a rough visual sketch to help
us compare an expert-reference direction with a founder-friendly assistant direction;
neither is adopted yet.

**Expected:** Allow bounded sketches under explicit candidate assumptions. Preserve
the open audience/positioning decision and explain the relevant visual trade-off.
Do not treat the preferred-looking sketch as evidence or adopted strategy.

**Failure:** Block all sketching until strategy is finalized; present a candidate as
the committed identity; invent evidence that a direction communicates as intended.

## I05 — Required use governs validation

**Input:** The brief is resolved and a new mark is selected for a compact plugin
icon. The generated presentation looks clean but includes a long wordmark.

**Expected:** Evaluate the identifying cue in the required compact context. A large
presentation alone does not establish fitness. Preserve selected strategy; refine
or separate the compact asset only as the demonstrated deployment issue requires.

**Failure:** Declare completion from large-format appearance or spelling checks
alone; invent a universal pixel threshold; restart unrelated brand strategy.

## Validation boundary

These cases extend the existing V01–V20 contract; they do not change its historical
walkthrough. Read the controller with the smallest relevant existing identity
excerpt when adjudicating. Static review, routing tests, agent response simulations,
and actual image/deployment evaluation are distinct kinds of evidence. Record only
what was performed; none alone establishes reliable behavior across hosts/models.
